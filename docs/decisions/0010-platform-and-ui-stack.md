# ADR-0010: Рантайм на одній станції і стек веб-UI

**Статус:** прийнято; пп. 1, 2, 3, 4, 6 реалізовано в S2 (2026-10-15), автентифікація (п. 6) — 2026-10-19, див. «Реалізація» нижче · **Див.:** [TARGET_ARCHITECTURE §8, §9](../TARGET_ARCHITECTURE.md), [ARCHITECTURE §3.10–3.11](../ARCHITECTURE.md)

## Контекст

Потрібен веб-UI для керування проєктами, запуску пайплайна, розмітки,
вибору цілей і місій. Залізо — одна робоча станція з Windows і RTX 4060
(8 GB). Попередні рішення: власний в'ювер (DECISIONS #3), без CesiumJS.

## Рішення

1. **Бекенд:** FastAPI (API v2 поруч із v1); черга задач у SQLite з одним
   GPU-слотом і кількома CPU-слотами; кожна задача — окремий процес-воркер
   (CUDA OOM не валить API); події через WebSocket.
2. **Render service 3DGS** — довгоживучий процес «поза → зображення»
   (перспектива/орто) для UI, семантики й ML.
3. **Фронтенд:** Vite + TypeScript + React; TanStack Query для серверного
   стану, Zustand для клієнтського; API-клієнт генерується з OpenAPI.
4. **Карта:** MapLibre GL JS (відкрита, без ключів) з OSM-тайлами для
   2D-контексту. Це узгоджується з DECISIONS #3: 3D-глобус не потрібен,
   власна 3D-сцена лишається основною.
5. **3D:** власний WebGL2-рендерер (Фаза 4.2, варіант B) як незалежний від
   React модуль `web/renderer` з оверлеями (полігони AP, коридори, фрустуми
   камер) і пікінгом через depth.
6. Redis/Celery, Docker і автентифікацію відкладаємо до появи кількох
   машин або користувачів; API слухає лише localhost.

## Альтернативи

* *Svelte/Vue* — менше бойлерплейту, але слабша екосистема компонентів для
  карт, таблиць і анотацій.
* *CesiumJS* — глобус і 3D Tiles з коробки, але суперечить рішенню про
  власний в'ювер і тягне велику залежність.
* *Celery + Redis* — зайві на одній Windows-станції.

## Наслідки

* Поточний `web/appGLSL.js` переходить у `web/legacy/` до кінця міграції;
  шейдерні рішення ADR-0001…0005 переносяться в новий рендерер.
* Потрібні збірка фронтенду в CI (eslint уже є) і e2e-smoke (Playwright) пізніше.

## Реалізація (S2, 2026-10-15) і відхилення від плану

* **Черга** — таблиці `jobs`/`job_events`/`workers` у тому ж `catalog.db` (міграція 0002),
  SQLite у WAL. Не «процес-воркер на задачу», а **довгоживучий воркер на клас ресурсу**,
  який для кожної задачі запускає окремий дочірній процес: той самий захист від OOM і
  збоїв, але один heartbeat і одне місце, що закриває run-и вбитих задач.
* **WebSocket** не має шини повідомлень: API опитує `job_events` (0.4 с) за курсором.
  Для однієї станції цього достатньо; заміна на LISTEN/NOTIFY — разом із PostgreSQL.
* **Zustand і генерація клієнта з OpenAPI** поки не знадобились: стан у TanStack Query,
  типи в `web/app/src/api/types.ts` вручну дзеркалять pydantic-моделі (перевіряє `tsc`).
* **Тайли карти** — лише безключові: OSM (у темній темі — інверсія яскравості растру
  засобами MapLibre) і супутник Esri World Imagery. CARTO-підкладки тепер потребують
  API-ключа, тому відпали. Проєкт некомерційний; атрибуція показується на карті.
* **3D** — класичний в'ювер (`web/`) у рамці сторінки `/app/viewer/...`; власний
  WebGL2-рендерер (п. 5) — у Фазі 4.2.
* **Render service (п. 2, 6.4)** — окремий процес поруч із API, а не частина воркера: API лишається
  без torch, а інтерактивному виду потрібна сцена в VRAM між запитами. Задачі черги так не
  працюють (процес на задачу). Платимо VRAM: сцена ≈ 100–400 MB на GPU, де йде й тренування, тому
  її вивантажують після простою, а OOM віддається як 503, не валить процес. Деталі —
  [ARCHITECTURE §3.12](../ARCHITECTURE.md).
* **П. 6, автентифікація (2026-10-19)** — більше не відкладена: доступ не з цієї машини вимагає
  токен, бо UI відкривають з інших машин. Redis/Celery/Docker лишаються відкладеними. Loopback
  відкритий як і раніше (без налаштувань), токени — файл хешів, а не таблиця каталогу (без нової
  ревізії Alembic); браузер — HttpOnly-cookie після входу, скрипти — Bearer. Деталі й відкинуті
  варіанти — [ARCHITECTURE §3.11](../ARCHITECTURE.md),
  журнал 2026-10-19 (внутрішній журнал). e2e-smoke (Playwright) —
  `web/app/e2e`, `npm run e2e`.
