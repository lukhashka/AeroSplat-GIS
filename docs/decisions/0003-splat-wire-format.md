# ADR-0003: Формат передачі сплатів = GPU-текстура

**Статус:** прийнято · **Мітки:** §3.1–§3.4, review-2 §2.1, §2.6

## Рішення

* **Запис 16 float** (`SPLAT16`): `xyz[0:3] opacity[3] scale[4:7] pad
  rotation(w,x,y,z)[8:12] rgb[12:15] pad` — рівно 4 RGBA32F-текселі, тож тіло
  відповіді завантажується як текстура без перепакування. Кожен інстанс несе
  один float (індекс сплата); сортування переписує лише його.
* Текстура шириною 2048 текселів (512 сплатів на рядок); буфер добивається
  нулями до цілого рядка.
* **Стеля адресації fp32:** шейдер адресує *текселі* (`aSplatIndex * 4.0`), тож
  ліміт — `2²⁴ / 4 = 4 194 304` сплатів, а не `2²⁴`. Понад нього множення
  неточне і сплати читають чужі дані (тиха корупція). Сервер і воркер
  попереджають і радять більший `?step=`.
* `GET /api/v1/scene-meta` (JSON) замість заголовків; `ETag` +
  `Cache-Control: must-revalidate`; ледаче завантаження за
  `(dataset, mode, step)` з LRU-кешем (~1.5 ГБ); `dataset` — параметр запиту.
* **Near-cull:** `uNearCull` у шейдері та `camera.near` виводяться з одного
  `near_cull_fraction` (0.001 радіуса), щоб не розходитись при зміні
  `TARGET_SCENE_RADIUS`.
* Воркер сортування віддає `Float32Array` (атрибути GLSL ES 1.00 — float);
  scratch-буфери виділяються один раз при `init`.
